# v0.16.0 Migration Checklist

Pre-deployment checklist for migrating from `ats_newstart` (v0.15.0, migration 033) to `ats_newstart2` (v0.16.0, migration 041).

## Overview

8 new migrations will run: **034 through 041**.

| Migration | Operation | Risk | Description |
|-----------|-----------|------|-------------|
| **034** | Alter existing table | **Medium** | Composite PK on `picklists (id, organization_id)` — backfills NULLs, deduplicates, drops/recreates PK |
| 035 | Add nullable column | Low | `agent_system_prompt` on `document_type_configs` |
| 036 | Add nullable column | Low | `agent_model` on `document_type_configs` |
| 037 | Create table | Low | `invitations` table (idempotent, has `table_exists()` guard) |
| 038 | Create 2 tables | Low | `agent_trace_runs`, `agent_trace_events` (idempotent) |
| 039 | Create 3 tables | Low | `transcription_sessions`, `transcription_participants`, `transcription_segments` (idempotent) |
| 040 | Create table | Low | `transcription_configs` (idempotent) |
| 041 | No-op | None | App-level enum change only (`pass`) |

Migration 034 is the only one that modifies an existing table with data. All others are additive (new columns or new tables) with idempotency guards.

## Pre-Flight Checks (Run Against Production DB)

Run these queries **before** deploying. All must pass.

### 1. Confirm current migration version

```sql
SELECT version_num FROM alembic_version;
```

**Expected:** `033`

If the result is already `034` or higher, some migrations have already been applied — adjust the plan accordingly.

### 2. Check picklists for NULL organization_id

```sql
SELECT COUNT(*) AS null_org_ids FROM picklists WHERE organization_id IS NULL;
```

**Expected:** `0`

If non-zero, migration 034 will backfill these to `00000000-0000-0000-0000-000000000001` (the default org). Verify this is the correct target org for your deployment.

### 3. Check picklists for duplicate (id, organization_id) pairs

```sql
SELECT id, organization_id, COUNT(*) AS cnt
FROM picklists
GROUP BY id, organization_id
HAVING COUNT(*) > 1;
```

**Expected:** 0 rows

If duplicates exist, migration 034 will keep the row with the earliest `created_at` and delete the rest. Review any duplicates before proceeding.

### 4. Verify PK constraint name

```sql
SELECT conname FROM pg_constraint
WHERE conrelid = 'picklists'::regclass AND contype = 'p';
```

**Expected:** `picklists_pkey`

Migration 034 calls `op.drop_constraint('picklists_pkey', ...)`. If the constraint has a different name, the migration will fail. If the name differs, update migration 034 before deploying.

### 5. Check total picklist count

```sql
SELECT COUNT(*) FROM picklists;
```

**Expected:** Small number (typically < 50). The DDL lock during PK recreation is proportional to table size — with a small table this is instant.

### 6. Verify no foreign keys reference picklists

```sql
SELECT conname, conrelid::regclass AS table_name
FROM pg_constraint
WHERE confrelid = 'picklists'::regclass AND contype = 'f';
```

**Expected:** 0 rows

If other tables have FK references to `picklists.id`, the PK change could cause constraint violations.

## Dry-Run Migration (Recommended)

Test the full migration against a copy of the production database.

```bash
# 1. Dump production DB
pg_dump -h <prod-host> -U <user> -d <prod-db> > prod_backup.sql

# 2. Restore to a test database
createdb ats_migration_test
psql -d ats_migration_test < prod_backup.sql

# 3. Run migrations
cd backend
DATABASE_URL=postgresql://<user>:<pass>@localhost/ats_migration_test alembic upgrade head

# 4. Verify final state
psql -d ats_migration_test -c "SELECT version_num FROM alembic_version;"
# Expected: 041

# 5. Verify picklists composite PK
psql -d ats_migration_test -c "\d picklists"
# Primary key should show (id, organization_id)

# 6. Verify new tables exist
psql -d ats_migration_test -c "
SELECT table_name FROM information_schema.tables
WHERE table_schema = 'public'
AND table_name IN (
  'invitations',
  'agent_trace_runs', 'agent_trace_events',
  'transcription_sessions', 'transcription_participants',
  'transcription_segments', 'transcription_configs'
)
ORDER BY table_name;
"
# Expected: all 7 tables listed

# 7. Verify new columns on document_type_configs
psql -d ats_migration_test -c "
SELECT column_name, data_type, is_nullable
FROM information_schema.columns
WHERE table_name = 'document_type_configs'
AND column_name IN ('agent_system_prompt', 'agent_model')
ORDER BY column_name;
"
# Expected: both columns present, nullable

# 8. Clean up
dropdb ats_migration_test
```

## Deployment Steps

```bash
# 1. Take a backup of production DB
pg_dump -h <prod-host> -U <user> -d <prod-db> -Fc > backup_pre_v0.16.sql

# 2. Put app in maintenance mode (optional, recommended for 034)
#    Migration 034 takes a brief DDL lock on picklists table

# 3. Deploy new code (ats_newstart2 merged to ats_newstart)

# 4. Run migrations
cd backend && alembic upgrade head

# 5. Verify migration completed
alembic current
# Expected: 041

# 6. Start/restart application

# 7. Smoke test
#    - Login works (superadmin role changes)
#    - Settings > Users page loads
#    - Settings > Agent Traces page loads (admin)
#    - New user registration flow works (org assignment)
#    - Invitation create/accept works
#    - Document upload with agent processing works
```

## Rollback Plan

If migration fails partway through:

```bash
# Check which migration we're stuck on
alembic current

# Roll back to 033 (pre-v0.16 state)
alembic downgrade 033

# Restore from backup if needed
pg_restore -h <prod-host> -U <user> -d <prod-db> -c backup_pre_v0.16.sql
```

**Note on 034 rollback:** The downgrade recreates a single-column PK on `id`. This will fail if multiple orgs now have picklists with the same `id` (e.g., two orgs both have "department"). In that case, restore from backup instead.

## Post-Deployment Verification

```sql
-- Migration version
SELECT version_num FROM alembic_version;
-- Expected: 041

-- Picklists composite PK is in place
SELECT a.attname
FROM pg_index i
JOIN pg_attribute a ON a.attrelid = i.indrelid AND a.attnum = ANY(i.indkey)
WHERE i.indrelid = 'picklists'::regclass AND i.indisprimary = true;
-- Expected: id, organization_id

-- New tables created
SELECT table_name FROM information_schema.tables
WHERE table_schema = 'public'
AND table_name IN (
  'invitations', 'agent_trace_runs', 'agent_trace_events',
  'transcription_sessions', 'transcription_participants',
  'transcription_segments', 'transcription_configs'
)
ORDER BY table_name;
-- Expected: 7 rows

-- New columns on document_type_configs
SELECT column_name FROM information_schema.columns
WHERE table_name = 'document_type_configs'
AND column_name IN ('agent_system_prompt', 'agent_model');
-- Expected: 2 rows
```
